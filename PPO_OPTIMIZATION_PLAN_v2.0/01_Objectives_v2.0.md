## 0) 版本演进说明

### v1.9 → v2.0 的核心转变

| 维度 | v1.9 (规则引导) | v2.0 (端到端学习) |
|------|----------------|-------------------|
| **核心理念** | 用 corridor/dir_pref 等规则"教"策略内切 | 让策略从物理后果"自然学习"内切 |
| **奖励函数** | 15+ 权重需平衡 | ≤4 个核心项 |
| **内切来源** | 显式 `dir_pref_weight` 奖励 | 隐式：高速过弯需平滑→效率压力驱动 |
| **科研价值** | "规则工程" | "真正的强化学习" |

### 为什么改变？

v1.9 的 B2a 实验反复调参但无本质改善（`corner_peak_abs_omega` 始终达到 MAX_ANG_VEL 极限），这证明：
1. 过多人为规则压缩了策略探索空间
2. 策略学会了"感知奖励切换"而非"几何平滑"
3. 权重平衡困难，容易陷入局部最优

## 1) 总目标（系统层面）

在轮廓误差容许带（tolerance band，±ε/2）约束下，让策略 π **自主学习**：

- **直线段**：高进给、贴线
- **拐角段**：在允差带内**自动发现**平滑过渡策略
  - 不强制"内切"，但期望策略自己发现"内切圆弧"是效率最优解
  - 核心洞察：急转弯→高角速度→KCM限速→效率降低→被时间惩罚
- **全程**：到达终点、无停滞、运动学约束由 KCM shielding 保证

> **关键转变**：我们不再"告诉"策略如何走拐角，而是通过**效率压力**让它自己发现最优解。

---

## 2) 核心假设（v2.0 的理论基础）

### 假设 H1：效率压力驱动平滑
```
急转弯 → 高角速度 → KCM 限制线速度 → 单步位移减少 → 完成轨迹需更多步数 → 累积时间惩罚增加
```
因此，**时间惩罚本身就是平滑的隐式激励**，无需显式 smoothness reward。

### 假设 H2：带内自由度足够
允差带宽度 ε=1.5mm，策略在带内有足够空间选择轨迹形状。只需保证"不越带"即可。

### 假设 H3：KCM 是充分的安全保证
运动学约束通过 action shielding 强制执行，无需在 reward 中重复惩罚。

## 3) 极简奖励函数设计

### 3.1 核心公式

```python
reward = r_progress + r_boundary + r_time + r_completion
```

| 奖励项 | 公式 | 权重建议 | 作用 |
|--------|------|----------|------|
| `r_progress` | `+w_s × Δprogress` | 20.0 | 唯一正向激励，驱动前进 |
| `r_boundary` | `-100 if |e_n| > ε/2 else 0` | - | 越带硬惩罚（非shaping） |
| `r_time` | `-0.01` | - | 每步固定惩罚，驱动效率 |
| `r_completion` | `+50 if reached_target` | - | 完成奖励（可选） |

### 3.2 删除的奖励项

| 删除项 | 原因 |
|--------|------|
| `r_track` (贴线惩罚) | 带内自由度被压缩 |
| `r_dir` (航向惩罚) | 过早约束策略选择 |
| `corridor_*` 全系列 | 显式规则，违背端到端 |
| `r_smooth` (平滑惩罚) | 效率压力已隐式包含 |
| `dir_pref_*` | 显式内切指令 |

### 3.3 为什么这样设计？

1. **正向只给进度**：策略唯一目标是"快速完成轨迹"
2. **负向只有时间**：每步都在"失血"，必须高效
3. **越带是硬约束**：不是 shaping，是禁区
4. **带内完全自由**：策略可以探索任何几何形状

## 4) 必须项（Paper-level Gate）

| 指标 | 条件 | 验证方式 |
|------|------|----------|
| 到达终点 | `reached_target = true` | summary.json |
| 不越带 | `max_abs_e_n ≤ ε/2` | trace 统计 |
| 效率不暴增 | `steps ≤ 1.2× baseline` | 对比 P0_L2 |
| 硬约束零违规 | KCM shielding 保证 | 机制保证 |

> **注意**：v2.0 放宽效率阈值到 1.2×（从 1.05×），因为初期探索可能需要更多步数。

## 5) 改善项（期望策略自然涌现）

### 5.1 期望涌现的行为

| 行为 | 物理解释 | 可测指标 |
|------|----------|----------|
| 拐角内切 | 减少转向激烈程度 → 可维持高速 | `inside_ratio > 0.5` |
| 轨迹平滑 | 避免急转 → 减少 KCM 降速 | `corner_peak_omega ↓` |
| 高速过弯 | 平滑轨迹允许更高速度 | `corner_min_v ↑` |

### 5.2 评估指标（观察用，非优化目标）

```python
# 这些指标用于验证假设，不作为奖励
observation_metrics = {
    "inside_ratio": "拐角期 turn_sign*e_n >= 0 的比例",
    "corner_peak_omega": "拐角期角速度峰值",
    "corner_min_v": "拐角期最低速度",
    "corner_sharpness": "拐角期曲率 p95",
    "mean_velocity": "全程平均速度",
    "steps": "完成轨迹所需步数",
}
```

## 8) 风险与备选

### 8.1 如果策略未涌现内切？

1. **首选**：增加时间惩罚权重（加大效率压力）
2. **备选**：加入轻量曲率状态（让策略"看到"曲率信息）
3. **最后**：加入极轻量的 `|dκ/ds|` 惩罚（曲率变化率）

### 8.2 如果步数暴增？

1. 检查 boundary penalty 是否过于严厉导致"绕路"
2. 考虑渐进式边界（soft boundary shaping）
