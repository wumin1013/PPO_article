## 0) 版本演进说明

### v2.0 → v2.1 的核心转变

| 维度 | v2.0 (极简奖励) | v2.1 (曲率感知) |
|------|----------------|-----------------|
| **核心假设** | 效率压力隐式驱动平滑 | 曲率感知 + 效率压力 = 可学习的平滑 |
| **状态空间** | 12维（无曲率信息） | 14维（含曲率 + 曲率变化率） |
| **奖励函数** | 极简4项 | **不变**，极简4项 |
| **关键洞察** | 策略看不到曲率，无法学习平滑 | 显式曲率信息使平滑可学习 |

### 为什么改变？

v2.0 Phase 30 实验证明：
1. **极简奖励设计是正确的**（训练收敛、任务完成）
2. **假设链条太隐式**（效率压力 → 平滑涌现 失败）
3. **策略找到了"安全局部最优"**：在拐角减速→转向→加速，满足约束但无平滑

**v2.1 的核心改进**：状态空间必须包含曲率信息，这不是"备选降级"，而是**架构前提**。

## 1) 总目标（系统层面）

在轮廓误差容许带（tolerance band，±ε/2）约束下，让策略 π **自主学习**：

- **直线段**：高进给、贴线
- **拐角段**：基于曲率感知，在允差带内**自动发现**平滑过渡策略
- **全程**：到达终点、无停滞、运动学约束由 KCM shielding 保证

> **v2.1 关键**：策略能"看到"自己的轨迹曲率，从而学会避免急转弯。

## 2) 核心假设（v2.1 修正版）

### 假设 H1'：曲率感知使平滑可学习

```
策略感知曲率κ → 高曲率→KCM降速→效率低 这个链条变得显式
                ↓
策略可以主动选择低曲率轨迹 → 维持高速 → 更高奖励
```

> **对比 v2.0**：v2.0 假设策略能从"后果"反推出"低曲率更好"，但这个反馈链太长。  
> v2.1 让策略直接"看到"曲率，缩短了学习路径。

### 假设 H2：带内自由度足够（继承自 v2.0）

允差带宽度 ε=1.5mm，策略在带内有足够空间选择轨迹形状。

### 假设 H3：KCM 是充分的安全保证（继承自 v2.0）

运动学约束通过 action shielding 强制执行。

## 3) 状态空间设计（v2.1 核心改进）

### 3.1 14维状态向量

```python
# 8维核心特征（继承 Phase 21）
core_keys = [
    "contour_error_norm",    # |e| / half_ε
    "e_n_norm",              # e_n / half_ε（带符号法向误差）
    "heading_error_norm",    # τ / π
    "velocity_norm",         # v / MAX_VEL
    "acceleration_norm",     # a / MAX_ACC
    "angular_vel_norm",      # ω / MAX_ANG_VEL
    "overall_progress",      # [0, 1]
    "dist_to_turn_norm",     # dist_to_turn / dist_enter
]

# 4维拐角感知特征（继承 Phase 21）
corner_keys = [
    "turn_angle_norm",   # turn_angle / π
    "turn_sign",         # +1 左转 / -1 右转 / 0 直线
    "corner_phase",      # 1.0 在拐角期 / 0.0 否
    "inside_signed",     # turn_sign × e_n_norm
]

# 2维曲率感知特征（v2.1 新增）
curvature_keys = [
    "kappa_norm",        # κ / κ_max（执行轨迹曲率）
    "dkappa_ds_norm",    # (dκ/ds) / (dκ/ds)_max（曲率变化率）
]
```

### 3.2 曲率计算方法

使用最近3个轨迹点拟合圆弧，计算曲率 κ = 1/R。

```python
# 三点定圆法
v1 = p1 - p0
v2 = p2 - p1
cross = abs(v1[0] * v2[1] - v1[1] * v2[0])
chord = norm(p2 - p0)
kappa = 2.0 * cross / (norm(v1) * norm(v2) * chord + ε)
```

## 4) 奖励函数设计（与 v2.0 相同）

### 4.1 核心公式

```python
reward = r_progress + r_boundary + r_time + r_completion
```

| 奖励项 | 公式 | 权重 | 作用 |
|--------|------|------|------|
| `r_progress` | `+20 × Δprogress` | 20.0 | 唯一正向激励 |
| `r_boundary` | `-100 if |e_n| > ε/2 else 0` | - | 越带硬惩罚 |
| `r_time` | `-0.02` | - | 效率压力 |
| `r_completion` | `+50 if reached_target` | - | 完成奖励 |

> **关键**：奖励函数保持极简，改进仅在状态空间。

## 8) 风险与备选（简化版）

### 8.1 如果曲率状态仍无效？

**最后手段**：加入极轻量曲率惩罚

```yaml
curvature_penalty:
  enabled: true
  weight: 0.001  # 单一参数，极轻量
```

这仍然比 v1.9 的 15+ 参数简单得多，且保持可解释性。
